# BarbPH Transmission Ledger — Automated Broadcast Footprint Spec

Status: **approved for implementation; public route locked as `/transmission-ledger/`; production not yet changed**.

## Purpose

The Transmission Ledger is a public, automatically generated record of what BarbPH actually televised and when.

It is not a manual publication archive and not a schedule. It is an evidence trail generated by the live viewing system itself.

## Public route

`/transmission-ledger/`

The publication article about the live telecast will contain only a routing link to this page.

## Core truth rule

**Scheduled is not the same as aired.**

Only content that actually reaches the public viewing surface may appear in the public Transmission Ledger as televised.

A feed that was selected, checked, or scheduled but never became visible is not public broadcast history.

## Event model

For every aired interlude/session, the logger records a START event and an END event.

Minimum public-safe fields:

- `event_id`
- `session_type` (`daily-discover`, `global-sky`, or another future approved telecast type)
- `started_at_manila`
- `ended_at_manila`
- `duration_seconds`
- `status` (`completed` or `interrupted`)
- `build_version` or release identifier when useful

For Global Sky, each live tile may additionally record:

- `feed_id`
- `city`
- `country`
- `timezone`
- `started_at_local`
- `ended_at_local`
- optional season/climate label if the same truthful model used on-screen supplied it

## Internal-only fields

The underlying technical log may also retain fields that do not need to be public, including:

- provider endpoint or internal source URL
- health-check result details
- retry counts
- skip/failure reason
- rights/clearance registry reference
- player/embedding diagnostics
- cache/deployment diagnostics

The public ledger should not expose sensitive operational details merely because they exist internally.

## Global Sky session rule

Global Sky runs for **2 minutes every 4 hours** when the production scheduler determines an interlude is due and a viable cleared live-feed set is available.

The public ledger should record the Global Sky interlude as one session plus the set of live feeds that actually appeared during that session.

Example conceptual public record:

- Global Sky — started 2026-08-27 16:00:00 PHT
- duration: 120 seconds
- feeds aired: Tokyo, Sydney, London, New York, etc. (dynamic; no fixed roster)
- status: completed

The exact city roster must come from the runtime event, never from a predefined marketing list.

## Feed failure handling

### Failure before visible

- log internally as skipped/failed;
- do not publish as aired;
- do not create a public footprint for that feed.

### Failure after visible

- feed may appear in the public ledger because it truly aired;
- mark that feed/session interrupted where appropriate;
- preserve its actual start/end timestamps rather than pretending it completed.

## Timestamp rules

- Manila time (`Asia/Manila`) is the canonical ledger timestamp.
- City-local timestamps are derived from the same event instant using the feed's registered IANA timezone.
- Store machine-readable ISO-8601 timestamps with offsets.
- Display formatting may be human-friendly, but must not discard the canonical machine timestamp.

## Immutability / correction rule

Broadcast footprints should be append-oriented.

Do not silently rewrite an old aired event because a later system state changed. If a factual correction is required, retain the original record internally and add an explicit correction/superseding record or correction metadata.

## Duplicate protection

Every aired session receives a deterministic or unique `event_id`.

The logger must reject duplicate START/END writes for the same event and should be safe against browser refreshes, retries, repeated callbacks, and edge retries.

## Storage architecture

Do **not** rewrite a GitHub JSON file for every broadcast. That would create unnecessary commits/deploys and make runtime logging fragile.

Use persistent runtime storage for event records, with a read-only public endpoint feeding `/transmission-ledger/`.

Preferred conceptual chain:

Telecast Controller
→ Event Logger
→ Persistent Event Store
→ Transmission Ledger Read Endpoint
→ `/transmission-ledger/`

Exact storage implementation will be chosen during the Netlify implementation pass.

## Public page behavior

The public ledger should feel like a broadcast record, not a server console.

It may expose:

- date/time
- telecast type
- locations actually aired
- local times
- duration
- completed/interrupted state

It should not expose:

- failed candidate feeds that never reached screen
- private diagnostics
- credential state
- raw rights-clearance notes
- internal provider URLs unless intentionally public

## Publication relationship

The publication article does not embed the full ledger.

It contains a routing link to:

**Transmission Ledger → `/transmission-ledger/`**

The ledger updates independently and automatically as new qualifying broadcasts occur.
